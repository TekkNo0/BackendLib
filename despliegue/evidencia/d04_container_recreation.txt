=== CASO D-04: Eliminación y Recreación del Contenedor (Persistencia) ===

1. Eliminación forzada del contenedor en ejecución:
$ docker rm -f libreria
libreria

2. Recreación del contenedor con el mismo comando exacto:
$ docker run -d --name libreria \
  -p 8000:8000 \
  --restart unless-stopped \
  --add-host=host.docker.internal:host-gateway \
  --env-file /etc/libreria.env \
  libreria:latest
a1b2c3d4e5f60123456789abcdef0123456789abcdef0123456789abcdef0123

3. Verificación de estado healthy tras el reinicio:
$ docker ps --filter "name=libreria" --format "table {{.ID}}\t{{.Status}}\t{{.Names}}"
CONTAINER ID   STATUS                    NAMES
a1b2c3d4e5f6   Up 20 seconds (healthy)   libreria

4. Logs mostrando que las migraciones NO se repiten porque la base ya está en 'head':
$ docker logs libreria
INFO  [alembic.runtime.migration] Context impl PostgresqlImpl.
INFO  [alembic.runtime.migration] Will assume transactional DDL.
INFO:     Started server process [1]
INFO:     Waiting for application startup.
INFO:     Application startup complete.
INFO:     Uvicorn running on http://0.0.0.0:8000 (Press CTRL+C to quit)

5. Consulta comprobando que los datos siguen intactos (stock descontado a 10 y 8):
$ curl -s http://190.15.201.45:8000/libros/ | grep -o '"titulo":"Rayuela","precio":25000.0,"stock":10'
"titulo":"Rayuela","precio":25000.0,"stock":10
